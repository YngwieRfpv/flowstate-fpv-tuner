Zwei Werkzeuge, ein Produktgedanke

Der Guide erklärt, warum eine Einstellung so aussieht. Der Tuner führt durch den Ablauf, der dorthin führt. Beide sind eigenständige Einzeldateien und laufen vollständig offline.

Ablauf

Wie eine Version ihren Platz findet

Von der Einzeldatei bis zur aufrufbaren URL sind es fünf Schritte. Jeder Schritt hinterlässt eine Spur, die man später prüfen kann.

Quelle

Die Anwendung liegt als einzelne HTML-Datei vor.

Einordnen

Projekt, Kanal, Datum, Größe und Prüfsumme landen in versions.json.

Einspielen

Prüfen

Struktur

Ein Repository, zwei Anwendungen

Kein Build, keine Abhängigkeiten, keine Serverlogik. Alles, was GitHub Pages braucht, ist die richtige Ordnerstruktur und eine .nojekyll-Datei. 

flowstate-fpv-tuner/
├── index.html              # dieser Hub
├── README.md               # Bedienungsanleitung
├── .nojekyll               # Jekyll aus
├── .github/workflows/
│   └── validate.yml       # Index prüfen
├── tuner/
│   └── index.html          # FlowState Tuner
├── guide/
│   └── index.html          # FPV Guide
├── assets/
│   ├── css/style.css     # Design-System
│   ├── js/hub.js          # Rendering, DE/EN
│   ├── data/versions.json # ← Quelle der Wahrheit
│   └── images/*.svg
├── docs/
│   ├── GITHUB_PAGES_SETUP.md
│   ├── RELEASE_PROCESS.md
│   └── releases/           # Notes je Version

    ├── install-versions.sh # Dateien einspielen

    └── validate.mjs        # Prüfung
index.html

Der Hub bleibt schlank: Er beschreibt und verlinkt, er enthält die Anwendungen nicht.

versions.json

Einzige Quelle für Versionen, Kanäle, Hashes und Reifegrad — zweisprachig.

tuner/ · guide/

Feste URLs pro Projekt. Eine neue Version ersetzt genau eine Datei.

.nojekyll

Verhindert, dass GitHub Pages Dateien mit Unterstrich oder bestimmten Namen wegfiltert.

docs/

Release-Notes und Prozesswissen versioniert neben dem Code.

Deployment

In drei Schritten online

Der Hub ist statisch. Nach dem Einspielen der Anwendungsdateien genügt ein Push auf main, damit GitHub Pages die Seite neu baut.

1

Versionen einspielen

Die Einzeldateien an ihren Platz kopieren — das Skript berechnet Hash und Größe und trägt beides in den Index ein.

$ ./scripts/install-versions.sh \
    --tuner  ~/Downloads/FlowState-Tuner-v4.8-alpha.1.html \
    --guide  ~/Downloads/FPV_Guide_DE.html
2

Prüfen

Der Validator kontrolliert Index, Dateien, Hashes und interne Links.

$ node scripts/validate.mjs

Dieselbe Prüfung läuft bei jedem Push in GitHub Actions.

3

Pushen

Committen und pushen — GitHub Pages baut die Seite danach automatisch neu.

$ git add -A && git commit -m "release: tuner v4.8-alpha.1" \
    && git push origin main

https://yngwierfpv.github.io/flowstate-fpv-tuner/

Pages-Einstellung

Unter Settings → Pages muss als Quelle der Branch stehen, der die Dateien enthält — üblicherweise main, Ordner / (root). Zeigt die Einstellung auf einen anderen Branch, wird die Seite nie aktualisiert.

Reifegrad — ehrlich benannt

Beide Ausgaben sind vorab: der Tuner Early Alpha, der Guide GitHub-Beta. Bestandene Quellprüfungen sind kein Nachweis für Browser-, Web-Serial-, FC- oder Flugverhalten. Props ab für Bench-Arbeit, und bei heißen Motoren, Desyncs oder unklarer Mechanik sofort aufhören.
